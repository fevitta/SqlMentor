  - `test_collector.py` (24): object type, stats, columns, indexes, constraints, DDL, batch, index map, full collect, view expansion, partitions

- **Docker setup**: MariaDB 10.6 no `docker-compose.yml` com performance_schema consumers
- **CI**: Jobs `check-mariadb-paths` + `integration-mariadb` com `workflow_dispatch`
- **3 bugs corrigidos** durante integração:
  - `batch_constraints`: coluna `TABLE_SCHEMA` ambígua em JOIN multi-tabela
  - `sql_runtime_stats`: `SUM_CPU_TIME` não existe no MariaDB 10.6
  - `to_json`: campo `db_type` ausente no output JSON
- **830 unit tests** continuam passando sem regressão

## Decisões tomadas

- **Database UPPERCASE**: Criado como `SQLMENTOR_TEST` (não via `MARIADB_DATABASE` env) para que `information_schema.TABLE_SCHEMA` case-match com `.upper()` do collector
- **User criado no init SQL**: Sem `MARIADB_USER`/`MARIADB_PASSWORD` env vars — controle total de grants via `01_setup.sql`
- **Grants**: `SELECT, REFERENCES, SHOW VIEW, EXECUTE` — mínimo necessário para info_schema visibility
- **performance_schema consumers**: `events-statements-current=ON`, `events-statements-history=ON`, `events-waits-current=ON` no startup
- **InnoDB TABLE_ROWS**: Assertions aproximadas (`> 900` não `== 1000`) por ser estimativa
- **Parser blocks**: Assertion `>= 1` para JOINs (MariaDB 10.6 usa duplicate JSON keys sem `nested_loop`)
- **SUM_CPU_TIME**: Substituído por `0` — coluna não existe no MariaDB 10.6 (é MySQL 8.0+)
