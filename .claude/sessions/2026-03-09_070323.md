# Sessão 2026-03-09 — T4: Refatorar collector.py → usar adapter

## Objetivo

Implementar T4 da Fase 1: remover a dependência direta de `import oracledb` do `collector.py`, roteando todas as operações de banco através do `DatabaseAdapter` para tornar o collector database-agnostic.

## O que foi feito

- Adicionados 3 métodos abstratos ao `QueryBuilder` ABC: `set_statistics_level`, `session_sid`, `prev_sql_id`
- Implementações Oracle dos 3 métodos com validação whitelist para `set_statistics_level`
- Fix crítico: lowercase em nomes de colunas no `OracleAdapter.execute_query` (`col[0].lower()`)
- Nova função `connect_with_adapter()` em `connector.py` retornando `tuple[adapter, connection]`
- Refatoração completa de `collector.py`: removido `import oracledb`, removido `_execute_query()`, removidos imports de `sqlmentor.queries` — tudo via `adapter.query_builder` e `adapter.execute_query()`
- Parâmetro `adapter` adicionado a `collect_context()` e ~15 funções privadas (backward compat via default `None`)
- `cli.py` e `mcp_server.py` atualizados para usar `connect_with_adapter()` e passar `adapter=adapter`
- Testes atualizados: `_make_adapter_mock()` helper, 661 testes passando, 94% cobertura
- Re-exports adicionados em `queries/__init__.py`
- T3 e T4 marcados como DONE em `docs/PHASE1_TASKS.md` (progresso: 6/9)
- Commit e PR #7 criados na branch `feat/collector-adapter-t4-v2`

## Decisões tomadas

- **Thin delegation**: collector mantém lógica de orquestração, adapter provê `execute_query()` e `query_builder`
- **Backward compat**: `adapter=None` em `collect_context()` faz lazy-import de `OracleAdapter()`
- **Merge de exceptions**: `except oracledb.DatabaseError` fundido com `except Exception` (detecção DPY-4011 é string-based)
- **Lowercase columns**: fix aplicado em `OracleAdapter.execute_query` pois todo código downstream espera keys minúsculas
- **ALTER SESSION via f-string**: whitelist validation (`ALL`, `TYPICAL`) — mesmo padrão do `explain_plan`
