# Sessao 2026-03-08 — Fase 1 Multi-DB: T1, T8, T9 + --version

## Objetivo

Implementar as 3 primeiras tarefas da Fase 1 do roadmap multi-DB (T1, T8, T9) e adicionar flag `--version` ao CLI com semantic-release automatizado.

## O que foi feito

- **T1 (PR #3, merged)**: Criou ABCs `DatabaseAdapter`, `QueryBuilder`, `PlanParser` em `src/sqlmentor/adapters/` com registry (register/get/list_adapters) e lazy import
- **T8 (PR #4, merged)**: Adicionou campo `type` (oracle|postgresql|mariadb) aos profiles de conexao em `connections.yaml`, com backward compat, validacao e `--db-type` no CLI
- **T9 (PR #5, merged)**: Adicionou parametro `dialect` ao parser com dicts por dialeto para system tables, builtin functions, sqlglot mapping e bind styles
- **--version**: Flag `--version` / `-V` no CLI via `importlib.metadata`, com python-semantic-release configurado
- **Review completo**: 4 reviewers paralelos (code quality, security, performance, test coverage) para cada task, com correcoes aplicadas
- **.gitignore**: Adicionou `.worktrees/` e `.claude/tasks.json`

## Decisoes tomadas

| Decisao | Razao |
|---------|-------|
| `PlanBlock` importado via `TYPE_CHECKING` guard | Evita import chain pesado (report->collector->oracledb) no startup |
| `db_type` normalizado com `.lower().strip()` | Case-insensitive lookups no registry |
| `NotImplementedError` guard em `connect()`/`test_connection()`/`diagnose_connection()` | Previne uso silencioso de oracledb para profiles nao-oracle |
| Validacao de `db_type` somente em write-time (`add_connection`) | Read-time validation redundante removida apos review |
| `_extract_from_plsql` tornado dialect-aware | Consistencia com path sqlglot que ja filtrava por dialeto |
| `python-semantic-release` para versionamento | Bump automatico baseado em conventional commits |
