### Bugs identificados
- **T10 (novo)** — EXPLAIN estimado falha com `%Y` em SQLs com DATE_FORMAT/STR_TO_DATE. PyMySQL interpreta `%Y` como format specifier quando params é `{}`.
- **T1 (reaberto)** — Parâmetros do Otimizador renderiza vazio em todos os 9 reports (13 params coletados, mismatch de keys)
- **T2 (reaberto)** — View Expansion Summary classifica tabelas como "não acessadas" mesmo quando o plano JSON mostra access. Root cause atualizado: `MariaDBPlanParser` não desce em `"materialized"`.

### Confirmações de fixes T1-T9

- **T7 OK** — VTAL usa `gso.` em vez de `SQLMENTOR.` (DDL e metadata coletados com sucesso)
- **T9 OK** — Literais `Cancelada`, `Fechado em WFM` não aparecem mais como colunas WHERE

### Investigação performance_schema para inspect MariaDB
- Descoberto que `events_statements_history_long` é OFF por default no RDS
- Consumer pode ser ativado via `UPDATE setup_consumers` (volátil)
- Parâmetros `performance-schema-consumer-*` **não existem** no Parameter Group do RDS MariaDB
- Workaround: Event Scheduler que reativa consumers periodicamente
- DIGEST do zeus obtido: `86d80b06393bd2fd0d7481b4e18ce5b3`

### T11 definida — inspect MariaDB via DIGEST
- Fluxo: buscar SQL_TEXT de `history_long` → ANALYZE → stats de `summary_by_digest` → metadata
- Se consumer OFF: abort com mensagem orientando ativação
- `sqlmentor doctor` ganha checagem dos consumers MariaDB

## Decisões tomadas

- **Plano estimado + runtime juntos**: descartado. ANALYZE do MariaDB já inclui `rows` (estimado) e `r_rows` (real) no mesmo JSON. Comportamento atual (sem execute → estimado, com execute → runtime) está correto.
- **`--sql` no inspect MariaDB**: removido. O SQL vem de `history_long.SQL_TEXT`. Se o consumer estiver OFF, o inspect aborta com orientação ao usuário em vez de exigir `--sql`.
- **Dependência de `history_long`**: aceita, com workaround via Event Scheduler documentado na task e no `doctor`.
