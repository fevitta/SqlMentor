## Objetivo

Implementar T2 (refatorar connector.py → OracleAdapter) e T3 (mover queries para OracleQueryBuilder), conforme plano detalhado fornecido pelo usuário. Criar PR para master.

## O que foi feito

- **T2 — OracleAdapter**: Criado adapter concreto implementando `DatabaseAdapter` ABC com connect (thin/thick fallback DPY-3010), validate_privileges (retorna dict, não levanta), diagnose_connection, execute_query (LOB .read() conversion), test_connection, close_connection
- **T2 — connector.py refatorado**: Removido `import oracledb`, `_thick_mode_initialized`, toda lógica Oracle-específica. Connector agora delega ao adapter via `get_adapter()`. Re-exporta `_init_thick_mode_if_available` e `check_thick_mode_available` do módulo oracle para backward compat
- **T2 — Testes**: 38 novos testes em `test_oracle_adapter.py`. Testes existentes em `test_connector.py` atualizados (patch targets, `ValueError` em vez de `NotImplementedError`)
- **T3 — OracleQueryBuilder**: Todas as 30+ queries Oracle inlinadas como métodos da classe. Helpers (`_validate_sql_id`, `_build_tuple_in_clause`) tornaram-se métodos estáticos
- **T3 — Re-export layer**: `queries/__init__.py` simplificado para delegar a uma instância singleton de `OracleQueryBuilder`
- **PR #6 merged**: feat/oracle-adapter-t2-t3 → master
- **656 testes passando**, zero regressões

## Decisões tomadas

- `OracleAdapter.validate_privileges()` retorna dict (não levanta) — connector wraps com PermissionError
- Exception type para db types não suportados: `ValueError` (via `get_adapter()`) em vez de `NotImplementedError`
- `OraclePlanParser` é stub com `NotImplementedError` (T5 implementará)
- SQL vive em `OracleQueryBuilder` (fonte única de verdade), `queries/__init__.py` é só re-export
- Thick mode state (`_thick_mode_initialized`) vive em `adapters/oracle.py` (módulo-level)
